The Challenge

A specialized commercial consulting firm — operating at the intersection of facilities design, operations analysis, and procurement strategy — had built a sophisticated proposal methodology over decades of practice. That methodology was the firm's primary competitive asset. It was also almost entirely undocumented and non-transferable.

New associates joined with strong domain knowledge but no structured pathway into the firm's proposal process. Proposal quality varied by individual. Knowledge transfer required senior practitioner time that scaled poorly. There was no self-directed learning option.

The Performance Gap

Junior staff required extensive mentorship for every proposal cycle. Senior practitioners spent disproportionate time on knowledge transfer instead of production. Institutional knowledge was fragile — dependent on individual tenure rather than documented systems.

The Design Brief

Build a self-directed, modular training system that encodes the firm's proposal methodology into a repeatable, media-rich learning experience — accessible in any browser, operable without a server or external platform, and maintainable by non-technical staff.

Discovery & Needs Analysis

◎
SME Interviews

Structured interviews with senior practitioners to surface tacit procedural knowledge, identify common failure points in new-associate onboarding, and extract the mental models underlying high-quality proposal work.

◈
Process Observation

Direct observation of proposal production cycles — from discovery intake through final document assembly — to identify the actual sequence of decisions, tools, and conventions the firm considers non-negotiable.

◻
Document Audit

Review of existing proposal archives, template files, reference materials, and internal procedure documentation to identify what was already codified, what was implicit, and what was missing entirely.

◧
Learner Profiling

Adult professionals with strong domain knowledge; time-constrained; self-directed in orientation. Learning must fit around active project work. Reference-over-completion access patterns anticipated.

◑
Gap Mapping

Structured comparison of current performance against target standards across each competency area — used to sequence module priorities and identify where immediate instructional intervention would have the highest leverage.

◐
Content Validation

All drafted content reviewed by subject-matter experts before build. Custom validation script enforced formatting standards, confirmed media embeds, and checked structural integrity before any module was finalized.

Curriculum Architecture

Fourteen modules organized into four competency tiers — each self-contained, each cross-referenced. The sequence moves from organizational foundations through production mechanics and into reference infrastructure. Learners may progress linearly or use modules as on-demand references.

Instructional Design Approach

Each design decision was made against a specific constraint or learning-science rationale — not as a feature list, but as a direct response to learner profile, content type, and deployment environment.

Spaced Repetition — Three Formats

Every module closes with flashcards in three simultaneous formats: flip-card (self-paced recall), grid (rapid scanning), and cut-card strip (physical or printed reference). Same content, three retrieval modes. Designed for diverse review habits and use contexts.

Knowledge Checks with Explanatory Legends

Multiple-choice quizzes are paired with answer legends that explain the correct reasoning — not just the correct letter. This extends the quiz from a test into a teaching moment, supporting learners who miss questions without requiring instructor involvement.

Multi-Modal Delivery per Module

Each module delivers the same core content through video, audio, slides, and infographic. This serves different access modes (commute, desk, reference), different learner preferences, and different levels of prior knowledge — without branching the instructional sequence.

Self-Contained HTML Format

All media — video, audio, images — is embedded as base64 within a single HTML file. No server required, no platform dependency, no network access needed after delivery. Files run in any browser and survive indefinitely without maintenance infrastructure.

Validated Content Pipeline

A custom Python validator enforces format standards before any module is finalized: no unauthorized names, no formatting violations, correct quiz counts, balanced HTML structure. Human review is not the last line of defense; the build system is.

Cognitive Load Management

Content is segmented into sub-sections with distinct entry points, visible codes, and navigation landmarks. Learners can access any sub-section directly from the sidebar without scrolling through prior content. Long-form reference material is separated into its own modules (L, M).

Content & Media Strategy

The system uses a consistent media stack across every content module — not because every format is equally effective for every learner, but because no assumption can be made about context of access or prior knowledge. Module N (calculators) is the exception: it delivers only interactive tools and a quiz, as the content is computational rather than conceptual.

Interface Design

The interface is a single-page HTML document — not a web application. All navigation is anchor-based; all state is client-side. The visual system uses a persistent sidebar, a top navigation bar, and a main content zone that transitions through four phases per module: cover → instructional sub-sections → knowledge check → flashcard review.

Production Stack

The system was built without a CMS, a framework, or a cloud deployment dependency. The priority was longevity and portability: files that work in any browser, now and in ten years, without a running server or third-party account.

Content Authoring
Claude (Anthropic)

Used to draft instructional prose from raw SME notes; enforce house-style rules; draft quiz questions and answer legends; validate content before build.

Build Pipeline
Python

Custom scripts for assembling module HTML, embedding base64 media, applying template structure, and running pre-release validation checks.

Video Processing
FFmpeg

H.264/AAC encoding with faststart flag for inline playback. Explicit audio stream mapping to prevent silent-video failures. Source and output verified with ffprobe before embedding.

Validation
Custom Validator Script

Zero-tolerance checks: unauthorized text, em-dash violations, unbalanced HTML structure, quiz/legend count mismatches, missing flashcard formats. Build blocked on any FAIL.

Image Processing
Pillow (Python)

JPEG at q82, alpha channel flattened to white. Slides at 1200px max width, infographics at 1600px. All images base64-embedded in final HTML.

Format / Delivery
Self-Contained HTML

Single-file delivery: all media embedded. No server, no internet connection, no dependency on external platforms required after distribution. Google Fonts linked for rendering; fallback stacks defined for offline use.

Interaction Layer
Vanilla JavaScript

Slide navigation, quiz scoring, flashcard flip mechanics, tab-switching for flashcard formats, and interactive calculators — all in dependency-free JS. No build step, no bundler.

Design System
CSS Custom Properties

Full token system defined in :root. Dark-mode and light-mode variants. Typography scale, spacing scale, callout system, sidebar, quiz, and flashcard components all derived from the same token set.
